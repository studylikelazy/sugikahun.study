# 01. ビジョンとコア・ゲームプレイループ

## 1. 高コンセプト

> **昼、町外れの廃工場で数千の実験ラインを自動化する。夜、その成果を首都高に持ち出して確かめる。
> 目的はただ一つ、筑波で59秒を切る「1台」を作ること。**

量産型の工場ゲームは「生産数」を増やす。本作は **生産数ではなく精度と知見（DATA）** を増やす。
ベルトコンベアの先にあるのは出荷トラックではなく、**ダイナモ、風洞、耐久ベンチ、そして1台のHERO CAR** である。

### 1.1 エレベーターピッチ（30秒版）

「Factorio の自動化を、JDMチューニングのR&Dに置き換えた。
ピストン1個の公差 0.01 mm を詰めるために、炉と研削盤と計測機のラインを組み、
夜は首都高C1で実走テレメトリを取って帰ってくる。
すべては週末、筑波のストップウォッチに表示される3桁の数字のためだ。」

### 1.2 三本柱（Design Pillars）

| # | 柱 | 意味 | 破ってはいけない線 |
|---|---|---|---|
| **P1** | **ENGINEERING IS THE GAME**（工学が遊びである） | 数値の裏に必ず物理的な理由がある。出力が上がるのは吸気効率が上がったからであり、「+10%カード」を引いたからではない | 因果不明のバフ／ランダムな強化 |
| **P2** | **ONE CAR, INFINITE FACTORY**（1台のために無限の工場） | 工場の規模は「販売量」ではなく「1台の完成度」に変換される | 完成車の量産販売を主収益にすること |
| **P3** | **THE NIGHT IS THE TEST BENCH**（夜は計測台である） | 夜の走行は娯楽であると同時に、研究の必須入力。走らない限り前に進まない | 夜パートを完全スキップ可能にすること |

### 1.3 デザイン・テネット（判断に迷ったときの優先順位）

1. **読み取れる因果 > 派手な数字**：ラップが0.4秒縮んだ理由を、プレイヤーが1画面で説明できること。
2. **手触りのある工学 > 正確な工学**：実機の再現度より、「触って学習できる勾配」を優先する。ただし嘘はつかない。
3. **静けさ > 賑やかさ**：工場は蛍光灯とコンプレッサーの音。夜は雨とタービンの音。UIが喋りすぎない。
4. **プレイヤーの設計 > 開発者の正解**：最速構成は1つに収束させない（`03` §11 ドライバビリティで担保）。
5. **中断可能 > 没入拘束**：どの瞬間でもセーブでき、1セッション20分で意味のある前進がある。

## 3. 二大柱の接合構造

```
                 ┌──────────────────── 昼：KOBO（工廠） ────────────────────┐
                 │  素材 → 加工 → 熱処理 → 計測 → 部品(等級付き)             │
                 │                   ↘ 試験体 → 試験設備 → DATA D1..D6     │
                 └──────────┬───────────────────────────┬────────────────┘
                            │ 部品を HERO CAR に装着     │ DATA で研究解放
                            ▼                           ▼
                 ┌──────────────── HERO CAR（1台） ────────────────┐
                 │  VehicleSpec（質量/トルク曲線/空力/タイヤ/剛性）   │
                 └──────────┬───────────────────────────┬─────────┘
       シャッターを開ける ──▶│                           │
                            ▼                           ▼
        ┌──── 夜：首都高 C1 / 湾岸 ────┐      ┌──── 週末：筑波 TC2000 ────┐
        │ 走る → テレメトリ・パケット   │      │ 走る → LAP TIME（進行ゲート）│
        │ 勝つ → 資金・評判・部品情報   │      │ 壊れる → 故障解析 → 新研究   │
        │ 捕まる → 罰金・押収（圧力）   │      └───────────┬───────────────┘
        └──────────┬───────────────────┘                  │
                   └──── 解析ラボ → D5 DATA ───────────────┘  → 昼へ戻る
```

**接合の鉄則**：どの矢印も片方向にならないこと。
工場 → 車 → 夜 → データ → 工場、という閉路が常に回っている状態を維持する。
ある柱だけを遊びたいプレイヤーのために「委託」機構（`05` §6.4）を用意するが、効率は必ず自走より劣る。

### 3.1 シャッター：シームレス遷移の仕様（確定仕様）

拠点の大型シャッターは、**ロード画面を挟まない演出的遷移点**である。

| フェーズ | 画面 | 仕様 |
|---|---|---|
| 1. 接近 | 工場クォータービュー | HERO CAR に乗り込むと、カメラが車両を中心に 1.8s かけてズーム＆回頭 |
| 2. シャッター | 工場→走行のクロス | シャッター開放の SE（チェーン駆動 + 金属の反響 2.4s）。外の雨音・環境音が 0.6s でクロスフェードイン |
| 3. 合流 | 疑似3D走行 | 車両は合流レーン上で初速 0 km/h。工場の内部状態は Worker 上で **動き続けている** |
| 4. 帰還 | 走行→工場 | ゲートセンサ通過で逆再生。帰還時に工場の進捗差分を「帰庫レポート」として提示（`06` §7.4） |

技術的には**シーンの切り替えではなく、レンダラの切り替え**である（`07` §6.5）。
シミュレーションスレッドは一切停止しない。これが「裏で工場が動いている」という本作の中核的な体感を作る。

## 4. コア・ゲームプレイループ（3階層）

### 4.1 ミクロループ（1–5分）：工場の1アクション

```
ボトルネックを見る → 原因を特定（在庫/電力/等級/工具摩耗）→ 設備を置く・繋ぐ・調整する
　→ ラインレートが変わる → 次のボトルネックが現れる
```
*目標*：**90秒に1回、「分かった」が起きる**こと。ボトルネック表示（`02` §13）はこのために存在する。

### 4.2 メゾループ（1ゲーム日 ≒ 14分）：昼と夜

| 時間帯 | ゲーム内時刻 | 実時間目安 | 主内容 |
|---|---|---|---|
| 朝 | 06:00–09:00 | 1.5分 | 帰庫レポート確認、夜のテレメトリ投入、発注、研究キュー設定 |
| 昼 | 09:00–18:00 | 7分 | **工場構築・拡張・デバッグ**（本作の総プレイ時間の約65%） |
| 夕 | 18:00–22:00 | 1.5分 | HERO CAR の整備・部品交換・セットアップ変更、準定常ソルバで机上評価 |
| 夜 | 22:00–03:00 | 4分（実走時は可変） | **首都高セッション**。目標カード3枚を消化して帰庫 |
| 深夜 | 03:00–06:00 | — | 工場は稼働継続。プレイヤーは就寝（スキップ）または深夜シフト操作 |

> 実時間は**プレイヤー操作で伸縮する**。時間倍率は `0.5x / 1x / 3x / 10x`（`07` §3.4）。
> 夜に出撃しない選択も可能だが、D5データが枯渇して研究が止まるため実質的に週2–3回は出る設計。

### 4.3 マクロループ（1ゲーム週 ≒ 90分）：筑波サイクル

```
月〜金：工場を伸ばす／夜に出る → 土：筑波の走行会（タイムアタック）
　→ タイムが出る／壊れる → 日：解析・反省・次週の設計目標を立てる → 月へ
```

- **土曜の走行会が本作の「ロケット打ち上げ」**。週に1度、すべての努力が3桁の数字に変換される。
- 走行会は隔週で `スポーツ走行枠`（いつでも走れるが公式記録にならない）と
  `公式計測会`（記録・クラス表彰・賞金あり）が切り替わる。
- 気温が低い冬季（12〜2月）は空気密度が高く **過給車に有利**。
  年間カレンダーがそのまま「記録を狙う季節」の読み合いになる（`03` §5.6 大気補正）。

チュートリアルは**テキストの説明ではなく、不可避な作業**として設計する。各段階に明示的な「分かる瞬間」を置く。

## 6. 時間制度

| 単位 | 定義 | 備考 |
|---|---|---|
| tick | 50 ms（20 tick/s） | 全シミュレーションの基礎 |
| ゲーム分 | 20 tick（1秒実時間 @1x） | 既定の時間倍率1xでゲーム内1分＝実1秒 |
| ゲーム日 | 1,440 ゲーム分 = 実24分 @1x / 約14分（夜スキップ時） | 深夜帯は自動早送り |
| ゲーム週 | 7日。土曜が走行会 | |
| 季節 | 春夏秋冬。気温 `T` と気圧 `p` が日毎に変動 | 空気密度 → 出力補正に直結（`03` §5.6） |
| 章（Act） | 7章。各章 8〜20ゲーム週 | |

### 6.1 時間倍率とオフライン進行

| 倍率 | 使用場面 | 制約 |
|---|---|---|
| 0.5x | 精密な建設・デバッグ | 回路のステップ実行は別機能 |
| 1x | 既定 | |
| 3x | ライン安定後の待ち | 夜パート中は不可 |
| 10x | 長時間の素材蓄積 | 近隣圧・故障イベント発生時に自動で1xへ戻る |

- **夜間出撃中も工場は動く**（別スレッドで同一tickを進める）。
- ゲームを閉じている間は進まない（＝真のオフライン進行なし）。ただし再開時に
  「夜間シフト（最大8ゲーム時間分）」を**素材生産のみ**まとめて適用する。DATA生成と研究進捗は対象外（判断ログ D-10）。

## 7. 章立て（Act 構成）と進行ゲート

各章は **「筑波の目標タイム」** と **「それを出すために必要な技術的ブレイクスルー」** のペアで定義される。

| Act | タイトル | 期間目安 | 筑波ゲート | 技術的主題 | 解放される工場要素 |
|---|---|---|---|---|---|
| **0** | 鍵と埃 | 1h | 1:12.000 | 手作業からの脱却 | ベルトI、マニピュレータI、切削機、ダイナモ |
| **1** | 等級という壁 | 4–6h | 1:06.000 | 公差と計測 | 研削盤、計測ゲート、熱処理炉、流体（切削油） |
| **2** | 過給の代償 | 6–8h | 1:02.000 | 過給・熱・ノック | 鋳造、シャシダイ、インタークーラー製造、電力増設 |
| **3** | 風を見る | 8–10h | 0:58.000（**分切り**） | 空力とダウンフォース | 縮尺風洞、CFDクラスタ、カーボン成形（オートクレーブ） |
| **4** | 壊れない強さ | 8–12h | 0:55.000 | 信頼性・材料・疲労 | 耐久ベンチ、4柱シェーカー、熱サイクル炉、冶金ラボ |
| **5** | 軽さの暴力 | 10–14h | 0:52.000 | 軽量化・剛性・特殊材 | チタン加工、放電加工、構造解析（FEM）、AGV物流 |
| **6** | 49秒の向こう | 12h+ | 0:49.999 | 統合最適化 | BP選別ライン、全自動セットアップ探索、フルオートメーション |

> **ゲートの検証**：上記タイムは参照実装 `shared/midnight/lap-solver.ts`（`03` §9 の準定常ソルバ）で
> 各章の想定スペック（`08` §7）を解いて確定した値である。**「物語の都合で置いた数字」ではない。**
> とくに **分切り（sub-60）は空力とSタイヤが揃う Act3** でしか起こらない——これは実車の世界と一致する。
> 最終ゲート **0:49.999** は、実在の TC2000 における非フォーミュラ最速（49秒445）の**すぐ手前**にある。
> つまり本作の到達点は「現実の最速クラスに並ぶ」ところであり、**48秒台という嘘はつかない**。

### 7.1 調達とゲートの関係

各Actのゲート突破に必要な部品は、**自作するか、4つの市場（`10`）から買うか**の二択になる。
市場で買える等級は **A 止まり**（S/BP は買えない）なので、章が進むほど「買う」では届かなくなる。
Act0〜1 は市場の比重が高く、Act4 以降は**市場は素材と車体の供給源に退く**——
この比重の移動そのものが、工場が育った実感になる。

### 7.2 ゲート設計のルール

1. ゲートは **タイムのみ**。資金や生産量をゲートにしない（P2の帰結）。
2. ゲート突破には「新技術 1つ」＋「既存ラインの品質向上」の**両方**が必要になるよう数値を置く。
   新技術だけ／品質だけでは 0.3〜0.6 秒届かないチューニングとする（`08` §7 進行曲線）。
3. 失敗しても損失はエントリー費とタイヤ摩耗のみ。**翌週また走れる**。
4. 各章の終わりに「章の総括レポート」：ラップのセクター差分、投入DATA、工場規模の推移を1枚で見せる。

## 8. 失敗・リスク・プレイヤーの心理曲線

| 失敗の種類 | 損失 | 回復手段 | 設計意図 |
|---|---|---|---|
| ラインが詰まる | 時間 | ボトルネック表示、ログ | 学習の主要経路。罰を与えない |
| ブレーカー遮断 | 数ゲーム分の停止＋違約金 | 契約見直し、デマンド制御の自動化 | 電力をパズルにする |
| 立入検査（近隣圧100） | 3ゲーム日の操業一部停止 | 防音・排気処理設備、夜間稼働制限 | 無制限拡張の抑止 |
| エンジンブロー | 当該部品の全損、1ゲーム週のロス | 予備ユニット（＝自動化の動機） | 「予備を作っておく」＝量産の再発明 |
| 検挙（夜） | 罰金、ヒート大幅増、累積で免停（3ゲーム日走行不可） | 時間帯・ルート分散、静音化 | 夜の緊張維持 |
| 車両押収（累積3回） | HERO CAR の一時没収（7ゲーム日）と改造の一部撤去 | 法務費用、車検対応仕様 | 最大のペナルティ。ただし恒久損失にはしない |

**心理曲線の狙い**：
章の序盤は「足りない」（欠乏）→ 中盤は「組み上がる」（有能感）→ 終盤は「あと0.2秒」（執着）。
この3拍子を7回繰り返す。土曜のアタックは毎回**執着のピーク**に置く。

## 9. 難易度とアクセシビリティ（概要）

| モード | 違い |
|---|---|
| **STREET**（易） | 近隣圧・ヒートの蓄積 50%、故障率 50%、資金 1.5倍、ゲートタイム +2.0秒 |
| **TUNER**（標準） | 既定値 |

  補助使用時も進行は一切ロックしない。ただし公式計測会の記録には `ASSIST` フラグが付き、オンラインランキングは別枠。
