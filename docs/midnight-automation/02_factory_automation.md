## 4. レシピ・システム

### 4.1 レシピの構造

```
Recipe {
  inputs:  [{ item, count, minGrade? }]
  fluids:  [{ fluid, amountPerCraft }]
  machine: MachineClass
  ticks:   基準所要時間（機械の speed で除算）
  outputs: [{ item, count, gradeRule }]
  byproducts: [{ item, count, probability }]   // 切粉、スラグ、廃油
  powerKw: 稼働時消費電力
  heatKw:  廃熱（§10 熱管理）
  noiseDb: 騒音（§10）
  toolWear: 工具摩耗の進行量（§9.3）
}
```

### 4.3 レシピ設計のルール

1. **工程は3〜6段**。それ以上は作業ではなく苦行になる。
2. 各工程に**明確な役割**を持たせる（形を作る／硬さを与える／精度を出す／保証する）。
3. 副産物（切粉・スラグ・廃油）は**必ず処理経路が要る**。放置すると近隣圧（§10）が上がる。
4. 等級の引き上げは**専用工程**（研削・ホーニング・選別）だけが担う。加工機の交換で勝手に上がらない。

| E85 / レース燃料 | 高負荷試験 | Act4 | 単価高・出力+・腐食性 |
| 圧縮エア | 工具、搬送、オートクレーブ | コンプレッサ | 消費ピークと電力デマンドが連動 |
| 排気（気体） | 炉・ダイナモから発生 | ダクト→触媒／スクラバー | 未処理で排出すると近隣圧+ |

温度は本作では**重要なゲーム変数**（冷却水温 → 試験可否、切削油温 → 精度）。

## 7. 電力システム（本作の固有パズル）

一般的な自動化ゲームは「総発電量 ≥ 総消費量」を満たせば終わりだが、
本作は **契約電力（デマンド）** という日本の工場特有の制約を中核に据える。

### 7.1 用語とルール

| 用語 | 定義 |
|---|---|
| 受電契約 | 契約電力 `P_contract [kW]`。基本料金 = `P_contract × ¥1,650/kW/月` |
| デマンド | **30ゲーム分の平均電力**。瞬時値ではない点が重要 |
| 超過 | デマンドが `P_contract` を超えると、当月の契約電力が自動改定（基本料金が恒久的に上がる） |
| 遮断 | 瞬時値が `P_contract × 1.3` を超えると主幹ブレーカー遮断 → 工場全停止（復旧 2ゲーム分） |
| 従量料金 | 昼 ¥22/kWh、夜間（22:00–08:00）¥12/kWh |

### 7.2 プレイヤーが打てる手

1. **契約を上げる**（金で解決。だが基本料金が重い）
2. **ピークシフト**：溶解炉・オートクレーブなど大電力設備を**夜間に動かす**（回路網でスケジュール制御）
3. **蓄電池**：ピーク時に放電、夜間に充電（ピークカット）
4. **自家発電**：ディーゼル発電機（騒音大）、ガスタービン（高効率・高熱）、太陽光（昼のみ・出力変動）
5. **インターロック**：同時起動を禁止する回路（例：溶解炉とオートクレーブの排他制御）

> **設計意図**：電力が「もう1つのベルト」になる。単なる前提条件ではなく、
> 時間軸上でのスケジューリングパズルとして機能させる。回路網（§12）を学ぶ最大の動機でもある。

## 8. 熱管理

| 発熱源 | 影響 |
|---|---|
| 溶解炉・熱処理炉 | 周囲タイルの温度上昇 → 近接する精密機械の Cpk 低下（熱変位） |
| ダイナモ・シャシダイ | 冷却水温上昇 → 規定温度超過で試験が中断・データ品質低下 |
| 変圧器・インバータ | 室温上昇 |
| オートクレーブ | 高温・高圧。安全距離の要求 |

**対策**：断熱壁、換気扇、ダクト、冷却塔、チラー、精密機械の恒温室（室温 20±1℃ で Cpk +15%）。

> 恒温室は Act4 の象徴的建造物。「精度のために部屋ごと空調する」という発想の転換をプレイヤーに起こさせる。

## 9. 品質システム：公差・等級・歩留まり（最重要）

### 9.1 等級

| 等級 | 公差 | 性能係数 `q` | 用途 |
|---|---|---|---|
| `C` | ±0.100 mm | 0.90 | 試験体、外販、消耗品 |
| `B` | ±0.050 mm | 1.00 | 標準。基準値 |
| `A` | ±0.020 mm | 1.06 | 実戦投入レベル |
| `S` | ±0.008 mm | 1.12 | 高出力・高回転に耐える |
| `LEGENDARY` | ±0.003 mm（選別・摺り合わせ） | 1.18 | HERO CAR 最終仕様 |

性能係数 `q` は部品ごとに異なる効き方をする（`03` §3.3）。
例：ピストン/コンロッドの `q` は**許容回転数と信頼性**に、タービンの `q` は**過給応答**に、
サスペンションアームの `q` は**アライメント再現性**に効く。単なる「全部+6%」にはしない。

### 9.2 等級の決定式

各加工ステップで、部品の寸法誤差 `e`（mm）を次式で生成する：

```
e ~ N(μ_drift, σ_proc)

σ_proc = σ_base(machine)
         × (1 + 0.60 × wear)              // 工具摩耗 0..1
         × (1 + 0.025 × max(0, T_env−22)) // 室温℃（22℃基準）
         × (1 + 0.30 × fluidContamination) // 切削油汚染 0..1
         × (1 − 0.35 × calibration)        // 校正・SPC補正 0..1
         × gradePenalty(inputGrade)        // 入力素材の等級が悪いと悪化

μ_drift = driftRate(machine) × ticksSinceCalibration   // 系統誤差（熱変位・摩耗）
```

等級は `|e|` を閾値表と比較して決定。複数工程を経る部品は **最悪値（ボトルネック工程）** が支配する
（＝「1箇所でも雑なら全部台無し」という工学的正しさ）。

工程能力指数：`Cpk = (T_upper − |μ_drift|) / (3 σ_proc)`（片側近似）。
UIには `Cpk` と**等級分布の棒グラフ**を機械ごとに常時表示する。

### 9.3 工具摩耗とメンテナンス

| 変数 | 挙動 |
|---|---|
| `wear` | 加工1回ごとに `toolWear` 加算。材質で倍率（チタン2.5x、インコネル3.5x） |
| 工具交換 | 自動（工具マガジンへのチップ供給ライン）／手動 |
| 校正 | 一定周期で `μ_drift` をリセット。CMMによる自動校正ライン（Act4）で無人化可能 |
| 切削油フィルタ | 汚染度を下げる。フィルタ自体が消耗品 |

> **これが本作最大の自動化題材**：工具チップ、切削油、校正、計測、不良の再投入——
> 「品質を維持するためのライン」が、部品を作るライン以上に巨大化していく。

### 9.4 選別・ブループリンティング（→ LEGENDARY 等級）

- `S` 級部品を複数投入し、**実測値のばらつきが揃った組み合わせ**を選び出す工程。
- 例：ピストン4個＋コンロッド4本を投入 → 重量差 ±0.5 g 以内の組が得られたら `LEGENDARY` セット成立。
- 成立確率は投入ロットの `σ` に依存：`P(LEGENDARY) ≈ erf(threshold / (σ√2))^n`
- → **「Legendary を1セット作るために、S級を大量生産する」** という、本作のフィロソフィーを最も体現するライン。

### 9.5 歩留まりの見える化

機械・ライン・工場の3スケールで表示：

```
LINE: PISTON #3        RATE 4.2/min   OEE 71%
 ┌ grade distribution ─────────────────┐
 │ C ████████ 32%   B █████████ 38%    │
 │ A ██████ 23%     S ██ 6%   LEGENDARY ▏1%   │
 └─────────────────────────────────────┘
 BOTTLENECK: GRINDER#2 (tool wear 0.81 → σ +49%)
```

## 10. 外部性：騒音・排気・排水・振動（近隣圧）

### 10.1 近隣圧（NUISANCE 0–100）

```
nuisanceRate = Σ_machines [ noiseFactor(dB, 時刻, 屋内外, 遮音) + emissionFactor + vibrationFactor ]
             × 住宅距離係数(lot)
             − mitigation(防音壁・吸音・触媒・集塵・緩衝緑地)
```

| 要素 | 内容 |
|---|---|
| 騒音 | 設備ごとの dB。**22:00–06:00 は係数 2.5 倍**（夜間規制）。屋内＋吸音で −12 dB、防音壁で −8 dB |
| 排気 | 炉・ダイナモ・発電機。触媒／スクラバーで 85% 削減 |
| 振動 | プレス、シェーカー。防振基礎で 70% 削減 |
| 排水 | 表面処理・切削油。油水分離＋産廃契約で 0。未処理は即時イベント |

### 10.2 段階的な反応

| 近隣圧 | 事象 |
|---|---|
| 0–29 | 平穏 |
| 30–49 | 苦情の投書（警告UI）。夜間稼働に注意喚起 |
| 50–69 | 町内会の訪問イベント（会話／寄付で −15、無視で +10） |
| 70–89 | **行政の立入検査予告**（3ゲーム日後）。期限までに騒音源を基準以下にできなければ改善命令 |
| 90–100 | **改善命令**：指定設備が3ゲーム日停止。罰金 ¥500k。解除には対策設備の設置が必要 |

### 10.3 緩和の設計意図

Factorio の汚染＝敵の襲撃に相当する「拡張のコスト」。
ただし本作では**破壊されない**。失うのは時間と金であり、やり直しの苦痛を与えない。
代わりに「夜間に静かな工場を作る」という**設計目標**を与える（静音ライン構成が上級者の腕の見せ所）。

## 11. 試験設備とDATA生成

工場の最終生産物は DATA である。各試験設備は「物理的に何かを壊す／回す／吹く」ことでデータを生む。

| 設備 | 投入 | 出力 | 所要 | 特徴 |
|---|---|---|---|---|
| **エンジンダイナモ** | エンジンユニット、ガソリン、冷却水、電力 | **D1 ベンチデータ** | 600 tick | 高騒音（102 dB）。過回転で破損リスク |
| **シャシダイ** | HERO CAR（占有）、燃料 | **D2 車両データ** | 400 tick | HERO CAR を占有＝夜に出られない。トレードオフ |
| **縮尺風洞** | 1/5 モデル（3Dプリント or 切削）、電力大 | **D3 空力データ** | 800 tick | 送風機が巨大な電力ピークを作る |
| **CFD／FEMクラスタ** | 電力、冷却、計算ノード | **D3/D6 解析データ** | 1,200 tick | 24時間稼働。夜間電力の主要消費者 |
| **耐久ベンチ** | テストピース（疲労）、作動油 | **D4 耐久データ** | 1,000 tick | 試験体を必ず破壊する＝消耗が激しい |
| **4柱シェーカー** | サスペンションASSY、電力 | **D4 データ** | 700 tick | 振動で近隣圧 |
| **熱サイクル炉** | 部品、電力、冷却 | **D4 データ** | 1,500 tick | 長時間。放置向き |
| **冶金ラボ** | 試料、試薬 | **D6 材料データ** | 900 tick | 新素材の解放に必須 |
| **解析ラボ** | テレメトリ・パケット（夜の成果）、電力 | **D5 実走データ** | 300 tick | **夜パートとの接続点** |

### 11.1 DATAの6分類

| ID | 名称 | 主な供給元 | 主に解放する領域 |
|---|---|---|---|
| **D1** | ベンチデータ | エンジンダイナモ | 燃焼、過給、吸排気、ECU |
| **D2** | 車両データ | シャシダイ | 駆動損失、トラクション、ギアリング |
| **D3** | 空力データ | 風洞、CFD | エアロ、冷却、床下 |
| **D4** | 耐久データ | 耐久ベンチ、シェーカー、熱サイクル | 信頼性、材料強度、サスペンション |
| **D5** | 実走データ | 解析ラボ（夜のテレメトリ） | セットアップ、タイヤ、ドライバ支援、路面 |
| **D6** | 材料データ | 冶金ラボ、FEM | 新素材、軽量化、加工法 |

研究ツリーの詳細は `05_tsukuba_progression_economy.md` §3。

### 11.2 試験の「質」

同じ D1 でも品質がある。`dataQuality = f(試験体の等級, 計測機の精度, 環境安定度, 試験回数)`。
高品質データは研究を **1.0〜1.6倍** の速度で進める。
→ 「とりあえず回す」より「ちゃんと測る」が強い、というエンジニアリング的な正しさ。

## 12. 制御（回路網 / PLC）

### 12.1 基本仕様

- 信号線は2系統（**赤線／緑線**）。各線は `(signalId → value)` の集合を運ぶ。
- 1 tick 遅延の同期更新（組合せループは1tick遅延で安定化）。
- エンティティは信号を**読む**（条件稼働）／**書く**（在庫量、稼働状態、温度、等級分布）。

### 12.2 本作固有の信号

| 信号 | 発信元 | 典型的な用途 |
|---|---|---|
| `DEMAND_KW` | 受電盤 | 契約電力に近づいたら大電力設備を停止 |
| `GRADE_A_COUNT` | 計測ゲート／倉庫 | A級が20個溜まったらブループリント選別ラインを起動 |
| `TOOL_WEAR` | 加工機 | 0.7 超で工具交換シーケンスを起動 |
| `TEMP_C` | 温度センサ | 恒温室の空調制御、冷却水温による試験の可否 |
| `CLOCK_HHMM` | 壁時計 | 夜間電力時間帯のスケジューリング |
| `NUISANCE` | 役所連絡盤（Act2） | 近隣圧が50を超えたら高騒音設備を停止 |
| `CAR_PRESENT` | HERO CAR リフト | 車庫にいる間だけシャシダイを有効化 |
| `STOCK[item]` | 倉庫／購買端末 | 在庫が閾値を切ったらカタログへ**自動発注**（Act2・`10` §9） |
| `MARKET_INDEX[slot]` | 相場ロガー（Act3） | 相場が安い週にまとめ買いする、高い週に出品する |
| `AUCTION_CLOSING` | 入札エージェント（Act4） | 締切が近い出品の通知。ルールに合えば自動入札 |

### 12.3 PLCブロック（上位）

Act3 で解放。**行指向のミニ言語**（1画面10行まで）を記述できる：

```
WHEN clock >= 22:00 AND clock < 06:00
  SET furnace.enable = true
  SET autoclave.enable = demand_kw < 900
WHEN tool_wear[mc_01] > 0.70
  PULSE tool_changer[mc_01]
  SET mc_01.enable = false FOR 20 ticks
```

> ビジュアル回路（結線）と文法（PLC）を併存させ、好みの方で同じことができるようにする。
> 文法側は**コピー＆ペーストで共有可能**（コミュニティでのレシピ共有を想定）。

### 12.4 解体ライン（Act5）

ヤードで買った「箱」を自動で処理する専用ラインを組める（`10` §4.3 / §9）。

```
[荷受けバッファ] → [洗浄] → [分解] ┬→ [計測CMM] → D2/D3データ
                                    ├→ [選別] → 使える部品 → 部品倉庫
                                    └→ [屑材] → 溶解炉 → 素材
```

計測CMMを通すことは**無料の鑑定**（`10` §8.1 レベル2）でもある。
つまり工場が育つほど、市場のランダム性は実質的に消えていく。
**「自動化が進むほど、博打が博打でなくなる」**——本作の成長実感はここに結晶する。

## 13. 情報設計：ボトルネックを「見える」ようにする

本作の学習は「なぜ止まっているか」が分かることに尽きる。以下を常設する。

| 機能 | 仕様 |
|---|---|
| **稼働オーバーレイ** | 全機械を `稼働中（緑）／入力待ち（黄）／出力詰まり（赤）／電力不足（紫）／停止（灰）` で色分け |
| **フローオーバーレイ** | ベルトの実スループット／理論値を太さと色で表示 |
| **ボトルネック・トレース** | 任意の機械を選ぶと、上流に遡って「最初に待たせている設備」までを線で結んで表示 |
| **ラインKPI** | ラインごとに `レート[個/分]`／`OEE`／`等級分布`／`消費電力` |
| **生産グラフ** | 直近 1/6/24 ゲーム時間のアイテム生産・消費の折れ線（Factorio 相当） |
| **DATAレート** | `D1..D6 の毎分生成量` を常時HUD表示。これが本作の「スコア」 |
| **ゴースト警告** | 設計図のうち材料不足で建たないものを一覧表示 |
