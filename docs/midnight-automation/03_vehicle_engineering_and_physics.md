# 03. 車両エンジニアリングと物理モデル

本書は HERO CAR のデータモデル、部品が性能に変換される数理、そして走行・ラップ算出のシミュレーションを定義する。
**原則**：ゲーム内のすべての性能値は、部品属性 → 物理量 → 挙動、という経路を通る。直接の「ステータス加算」は存在しない。

---

## 1. HERO CAR の全体構造

```
HeroCar
 ├ Chassis          ベース車両（1台のみ。章進行で乗り換え可だが推奨されない）
 ├ Powertrain
 │   ├ Engine       ブロック/ヘッド/カム/バルブ/ピストン/コンロッド/クランク/オイル系
 │   ├ Induction    インマニ/スロットル/ターボ or NA/インタークーラー/配管
 │   ├ Exhaust      エキマニ/タービン/ウェイストゲート/触媒/マフラー
 │   ├ Fuel         インジェクタ/ポンプ/レギュレータ/燃料種
 │   └ ECU          点火マップ/燃料マップ/ブースト制御/保護ロジック
 ├ Drivetrain       クラッチ/ミッション(6速)/ファイナル/LSD/ドライブシャフト
 ├ Suspension       ダンパー/スプリング/アーム/スタビ/ブッシュ/アライメント
 ├ Brakes           キャリパー/ローター/パッド/マスター/バランサー
 ├ Tires            銘柄/サイズ/内圧/温度/摩耗
 ├ Aero             フロントリップ/カナード/フロア/ディフューザー/GTウィング/ボンネット
 ├ Body             ボンネット/フェンダー/ドア/窓/内装撤去/ロールケージ/補強
 └ Setup            連続値のセッティング（§10）
```

各部品インスタンスは **「設計（PartDef）」×「製造結果（等級・実測値）」** の2層で表現される。
同じ設計のピストンでも、工場の出来によって性能と信頼性が変わる（`02` §9）。

```ts
type PartInstance = {
  defId: PartDefId;          // 設計
  grade: "C" | "B" | "A" | "S" | "LEGENDARY";
  measured: Record<string, number>; // 実測値（重量[g], 寸法誤差[mm], バランス[g·cm] 等）
  wear: number;              // 0..1
  heatCycles: number;        // 熱疲労の履歴
  serial: number;
};
```

### 2.1 個体差 ― 「どのシルビアを買ったか」が性能を決める

同じ **S15** でも、**手に入れた個体によって上限が変わる**（入手は `spec/S3` の4大市場）。

| パラメータ | 範囲 | 効き方 |
|---|---|---|
| 走行距離 | 5千〜240千 km | 消耗、オーバーホール費 |
| **フレーム歪み** | 0〜8 mm | **ねじり剛性 −0.045 /mm**。>6 mm は矯正不能 |
| 腐食 | 0〜1 | ねじり剛性 −0.08、溶接工数 |
| ナンバー | 有無 | 無しは公道に出られない＝夜パート不可 |

```
剛性係数    = 1 − 0.045 × 歪みmm − 0.08 × 腐食
実効グリップ = μ0 × clamp(0.88 + 0.12 × 剛性係数, 0.60, 1.05)   （剛性係数 1.0 = 新車）
```

剛性係数 0.80 の車体は μ が 2.4% 落ちる。`08` §7.1 の感度表で言えば **筑波で約 +0.6 秒**——
480 PS を 400 PS に落とすより重い損失である。
**車体が歪んでいるなら、エンジンを何基作っても報われない。**

逆向きも成立する。**レストアを完遂した車体（剛性係数 1.37）は μ が +4.4%**＝筑波で約 **−0.9 秒**。
納屋で朽ちていた個体が、最終的に新車より速くなる（`spec/S4` §5.1）。
上限 1.05 を置いているのは、「剛性だけ上げれば勝てる」を防ぐため——
剛性はある点から先、タイヤの仕事を邪魔しなくなるだけで、それ以上は速くならない。

> **乗り換えの設計**：ベースを変えると、専用設計の部品（ブロック、マウント、ハーネス、エアロ型）が作り直しになる。
> 「1台を仕上げる」というフィロソフィーのため、乗り換えは**可能だがコストが重い**。
> Act6 時点で乗り換える選択は、終盤の大きな決断イベントとして演出する。

## 4. 吸排気・燃焼モデル（4ストローク往復機関）

### 4.1 空気質量流量

```
ρ_in = p_man / (R_air × T_in)          R_air = 287 J/(kg·K)
ṁ_air = VE(rpm, p_man) × ρ_in × V_d × (rpm / 60) / 2      [kg/s]   ※4ストローク
```

- `V_d`：総排気量 [m³]
- `VE`：体積効率。カム・ポート・インマニ・排気から合成（§4.2）
- `p_man`：インマニ圧 [Pa]（NAは大気圧×吸気損失、過給は §5）

### 4.2 体積効率 VE の合成

```
VE(rpm) = VE_base(rpm; camLift, camDuration, overlap)
        × portFlowFactor(C_f, valveArea, rpm)
        × runnerTuningFactor(runnerLength, rpm)     // 慣性過給の山
        × exhaustFactor(manifoldType, backPressure)
        × clamp(1 − throttleLoss(throttleArea, rpm), 0.2, 1.0)
```

実装は **rpm 500 刻みのテーブル＋Catmull-Rom 補間**。
ハイカム（作用角大）は低回転で VE が落ち、7,000 rpm 以上で伸びる——という形状の変化が
**ゲーム内で体感できる**ことが重要（低速トルクが痩せる＝夜の市街地では扱いにくい）。

### 4.3 燃料と熱効率

```
ṁ_fuel = ṁ_air / AFR
P_ind  = ṁ_fuel × LHV × η_th(λ, 点火時期, 圧縮比, ノック余裕)
LHV: ガソリン 44.0 MJ/kg / E85 29.2 MJ/kg（ただし λ が低く設定でき冷却効果が大きい）
η_th ≈ η_otto(ε) × f_λ(λ) × f_spark(Δθ)
η_otto(ε) = 1 − ε^(1−γ)      γ = 1.30（作動ガスの実効比熱比）
```

### 4.4 摩擦損失と正味トルク

```
FMEP [kPa] = a + b·(rpm/1000) + c·(rpm/1000)²      // 部品の q と潤滑で a,b,c が変わる
P_fric = FMEP × V_d × (rpm/60) / 2
P_net  = P_ind − P_fric − P_aux(オルタ, ポンプ, エアコン撤去で削減)
T_net  = P_net / (2π × rpm / 60)      [N·m]
```

出力表示は PS（`1 PS = 735.5 W`）とkW併記。ダイナモ画面ではトルク／出力の2軸グラフを描く。

## 5. 過給モデル

### 5.1 目標ブーストと実ブースト

```
p_target(rpm, throttle) = ECUのブーストマップ（ウェイストゲート制御）
τ_spool(rpm, exhaustEnergy) = τ0 × (J_turbo / J_ref) × (rpm_ref / rpm)^0.85 / q_turbine
dp/dt = (p_target − p) / τ_spool                         // 1次遅れ
```

- 小径タービン：`τ_spool` 小（レスポンス良）だが高回転で `p_max` が頭打ち（チョーク）。
- 大径タービン：低回転で `τ_spool` 大（ドッカン）だが高回転で伸びる。
- **ボールベアリング化**（Act4）で `J_turbo` −25%、**ツインスクロール**で低回転の `exhaustEnergy` +18%。
- アンチラグ【P2】：排気温が跳ね上がり寿命が激減する、というトレードオフつきで実装検討。

### 5.2 インタークーラー

```
T_after = T_comp − ε × (T_comp − T_ambient)
p_man   = p_comp − Δp_ic(ṁ_air)
```
- 大型IC：`ε` 向上、しかし `Δp` 増・重量増・**前面投影面積が増えて Cd 悪化**。
- 空力と冷却の競合を意識させるため、IC・ラジエータ・オイルクーラーはすべて `Cd` へ寄与する。

### 5.3 ノッキング

```
KnockIndex = k1·(p_man/100kPa)^1.6 × k2·(T_in/300K)^2.2 × k3·(ε/9.0)^1.8
           × k4·exp(0.12 × Δθ_advance) / octaneRating / coolingMargin
```

- `KnockIndex > 1.0`：ECU がリタード（出力低下）／ECU非対応なら**ピストン溶損**（部品全損）。
- 対策：IC強化、点火リタード、燃料濃いめ（λ↓）、ハイオク／レース燃料、圧縮比を下げる、水メタ噴射（Act5）。
- **プレイヤーが初めて壊す場面**として Act2 に必ず起こるよう調律する（学習イベント）。

### 5.4 熱モデル

```
dT_water/dt = (Q_engine − Q_radiator(v, T_water, ρ_air)) / C_water
dT_oil/dt   = (Q_friction + Q_blowby − Q_oilcooler(v)) / C_oil
```
- 油温 130℃ 超：油膜切れ → 摩耗加速、140℃ でメタル損傷判定。
- 水温 110℃ 超：出力リミット、115℃ でオーバーヒート（走行中断）。
- 筑波では **5周目以降に熱が効いてくる**ため、アタックは「3周目にタイムを出す」計画が定石になる。

### 5.5 ロータリーエンジン（RX-7 / 13B-REW 専用モデル）

- 行程容積 `V_d_eq = 654cc × 2 × 2`（1回転2燃焼の等価換算）としてトルクを算出。
- 高回転まで VE が落ちにくい／熱負荷が大きい／燃費が悪い／アペックスシール寿命（`D4` 研究で延命）。
- サウンドと挙動の差別化を最優先。数式の厳密さより**別物であること**を体感させる。

### 5.6 大気補正

```
ρ_air = p_atm / (R_air × T_amb) × (1 − 0.378 × p_vapor / p_atm)
出力補正係数 CF = (p_std/p_atm) × sqrt(T_amb/T_std)        // JIS/SAE 相当の簡易式
```
- 冬の冷えた朝（気温 2℃、高気圧）は過給車に有利。夏の雨の夜は不利。
- 公式計測会の記録には気温・路面温度・気圧を必ず併記する。**記録狙いの季節選択**が戦略になる。

## 6. 駆動系

```
T_wheel = T_net(rpm) × i_gear × i_final × η_drive × (1 − slipLoss)
rpm     = v × i_gear × i_final × 60 / (2π r_eff)
m_eff   = m + (I_wheel×4 + I_drive)/r_eff² + I_eng × (i_gear × i_final)² / r_eff²
```

| 要素 | モデル |
|---|---|
| クラッチ | 容量 `T_cap`。超過で滑る（熱を持ち、焼ける） |
| シフト | シフト時間 `t_shift`（ドグ化で 0.25s→0.08s）。その間トルク0 |
| LSD | 差動制限トルク `T_lsd = T_initial + k_accel × T_input`。立ち上がりのトラクションと旋回性のトレードオフ |
| 4WD | トルク配分（固定／センターデフ／電子制御）。前後の荷重移動と連動 |
| 駆動損失 | FR 0.88 / 4WD 0.82 / MR 0.90（部品の `q` で ±0.02） |

**ギアリング設計**は本作の重要なミニゲーム。
`筑波で2速が足りない` `C1で5速が使えない` といった具体的な課題として提示し、
ギア比セットを工場で削り出す（＝製造対象）という形で自動化と結びつける。

## 7. タイヤモデル

簡易 Pacejka（Magic Formula）を縦・横に適用する。

```
F = D · sin( C · arctan( B·s − E·(B·s − arctan(B·s)) ) )
D = μ(Fz, T_tire, p_tire) · Fz
μ(Fz) = μ0 · (Fz / Fz_ref)^(−k_load)          k_load ≈ 0.12〜0.22（荷重感度）
μ ×= tempFactor(T_tire)   // 温度ウィンドウ外で最大 −18%
μ ×= pressFactor(p_tire)  // 最適内圧から外れると接地形状が崩れる
μ ×= (1 − 0.35·wear^1.8)  // 摩耗
μ ×= surfaceFactor(路面, 濡れ, 路温)
```

複合入力は**摩擦円**で制限：`sqrt((Fx/Fx_max)² + (Fy/Fy_max)²) ≤ 1`。

| 銘柄区分 | μ0 | 温度ウィンドウ | 摩耗率 | 用途 |
|---|---|---|---|---|
| コンフォート | 0.95 | 広い | 低 | 街乗り |
| スポーツラジアル | 1.12 | 60–85℃ | 中 | 夜のC1 |
| ハイグリップラジアル | 1.28 | 70–95℃ | 中高 | ストリートクラス |
| Sタイヤ | 1.45 | 80–105℃ | 高 | Sタイヤクラス |
| スリック | 1.62 | 85–110℃ | 最高 | アンリミテッド（公道不可） |
| ウェット | 1.05（湿） | 40–70℃ | 中 | 雨 |

タイヤ温度は `dT/dt = (滑りによる発熱 + 路面熱伝達 − 放熱)/C_tire` で周回ごとに更新。
**1周目は冷えていて遅い**、**4周目以降は垂れる**——タイムアタックの核心的な駆け引きを作る。

## 8. 空力

```
F_drag = 0.5 · ρ_air · Cd · A · v²
F_down(front) = 0.5 · ρ_air · Cl_f · A · v²
F_down(rear)  = 0.5 · ρ_air · Cl_r · A · v²
空力バランス = Cl_f / (Cl_f + Cl_r)   （目標 38–44%）
```

| 部品 | ΔCd | ΔCl_f | ΔCl_r | 備考 |
|---|---|---|---|---|
| フロントリップ | +0.010 | +0.12 | 0 | 最低地上高と干渉 |
| カナード ×4 | +0.014 | +0.09 | 0 | 公道では破損しやすい |
| フラットフロア | −0.012 | +0.06 | +0.04 | 車高が低いほど効く |
| リアディフューザー | −0.008 | 0 | +0.18 | フロアとセット |
| GTウィング（小） | +0.035 | 0 | +0.28 | 角度調整で可変 |
| GTウィング（大） | +0.062 | 0 | +0.52 | 筑波向き。C1では最高速を削る |
| ボンネットダクト | +0.004 | +0.03 | 0 | 水温対策と両立 |
| 牽引フック／ミラー等 | +0.006 | 0 | 0 | レギュレーション由来 |

**トレードオフの体感設計**：
- 筑波 TC2000 は最高速が 160–170 km/h 域のテクニカルコース（`README` §6 出典）。ダウンフォースが効く。
- 一方 C1／湾岸の最高速勝負ではウィングが明確な足枷になる。
- → **「2つの舞台で最適解が違う」**ことがエアロ着脱・可変ウィングという遊びを生む。

## 9. ラップタイム算出：準定常ソルバ（QSS）

プレイヤーが実走しなくても理論ラップを求められる計算器。
工場の「シミュレーション棟」（CFD/FEMクラスタ）で動作し、セットアップ比較に使う（判断ログ D-11）。

### 9.1 入力

- `TrackModel`：区間列（長さ、曲率半径 `R`、勾配、バンク角、路面μ、縁石使用可否）
- `VehicleSpec`：質量、重心、トルク曲線、ギア、空力、タイヤ、ブレーキ
- `Conditions`：気温、路温、気圧、風、燃料搭載量

### 9.2 アルゴリズム

```
1) コースを 2 m 刻みのノードに離散化
2) 各ノードの旋回限界速度 v_lat を不動点反復で解く：
      v ← sqrt( μ_lat(Fz(v)) · (m·g·cosθ + F_down(v) + m·g·sinφ_bank) · R / m )
   （F_down が v に依存するため 4〜6 回で収束）
3) 前進パス：v[i+1]² = v[i]² + 2·a_long(v[i])·Δs
      a_long = (min(F_engine, F_traction_limit) − F_drag − F_roll − F_grade) / m_eff
      摩擦円で横Gを使っている分だけ縦方向の余力を減らす
4) 後退パス：v[i]² = v[i+1]² + 2·a_brake(v[i])·Δs
      a_brake は μ・ダウンフォース・ブレーキ熱容量・前後バランスで制限
5) v[i] = min(前進, 後退, v_lat)
6) t = Σ 2·Δs / (v[i] + v[i+1])  ＋ シフト時間 × 変速回数
7) 補正：
      t_actual = t_ideal × (1 + penalty_driveability(§11) + penalty_traffic + penalty_tireDeg(lap))
```

### 9.3 出力

- 理論ラップ、セクタータイム、速度トレース、G-Gダイアグラム、使用ギア、各コーナーの限界要因
  （`タイヤ` / `パワー` / `ダウンフォース` / `ブレーキ熱` / `トラクション`）
- **限界要因の表示が最重要**：「第2ヘアピンはトラクション不足」と分かれば、次に作る部品が決まる。

### 9.3.1 参照実装

本ソルバは **`shared/midnight/lap-solver.ts` として実装済み**（依存なしの純関数）。
`shared/midnight/tsukuba.ts`（TC2000 コースデータ）と組み合わせて即座に実行でき、
`08` §7 のバランス表はこの実装で検証されている。実装上の要点：

| 項目 | 実装 |
|---|---|
| 離散化 | 2 m 刻み。周回コースは前進・後退パスを3巡させて収束 |
| 旋回限界 | ダウンフォースが速度依存のため、緩和係数 0.7 の不動点反復（8回） |
| ギア選択 | 「レブリミットを超えない最も低いギア」＋ヒステリシス 0.94（**シフトのハンチング防止**） |
| 変速損失 | 時間を加算せず、`v × shiftTime` の距離だけ駆動力を 0 にする。**ノード境界で丸めず、覆われた割合だけ駆動力を減らす**（丸めると「+10 PS で遅くなる」量子化ノイズが出る） |
| トラクション | 摩擦円 × 駆動輪荷重（荷重移動を2回反復で近似）。AWD は総グリップ |
| 走行ライン | 実効半径 = 幾何半径 × 1.00（縁石不可）／× 1.06（縁石使用可）。この2係数が**コース全体の速さを決めるキャリブレーション点**で、実在のコースレコードに合わせて決めた |

> **キャリブレーションの手順**：(1) 区間長の合計を公称全長（TC2000 なら 2,045 m）に一致させる →
> (2) 走行ライン係数を動かし、最強スペックの理論ラップが**実在の最速記録**（非フォーミュラ 49秒4台）に
> 並ぶ位置で固定する → (3) そのうえで各Actのスペックを置き、ゲートとの余裕を 0.2〜0.8 秒に揃える。
> 順序を逆にすると、スペック表が現実から乖離したまま辻褄だけが合う。

> **設計上の注意**：変速損失を「時間の加算」で実装すると、ギア境界で加速と減速が振動し、
> 「軽くすると遅くなる」といった**非物理的な感度**が発生する（開発中に実際に観測した）。
> 必ず駆動力の欠落として扱うこと。

### 9.4 実走との関係

| | QSS ソルバ | 実走（プレイヤー） |
|---|---|---|
| 速度 | 一瞬（数ms） | リアルタイム |
| 誤差 | 理論値。実走より 0.5〜1.5 秒速い | — |
| 用途 | 方向性の決定、A/Bテスト、自動探索 | 公式記録、ドライビングの楽しみ |

公式記録は**必ず実走**（またはAIドライバー委託＝`05` §6.4、ただし 0.8〜2.0 秒遅い）で取る。
机上で全部終わらないようにするための線引き。

## 11. ドライバビリティ（扱いやすさ）

最速スペック＝最速タイムにしないための中核システム。

```
driveability = w1·powerBandWidth      // 最大トルクの85%以上を維持するrpm幅
             + w2·boostOnsetSmooth    // dP/drpm のピーク（ドッカン度の逆数）
             + w3·balanceStability    // アンダーステア勾配が適正域にあるか
             + w4·snapResistance      // 過渡のヨー応答が発散しにくいか
             + w5·brakeStability      // 制動時の安定
             + w6·tractionMargin      // 立ち上がりのホイールスピン余裕
             − penalty(過大ばね定数, 過大キャンバー, 極端なLSD, 無理なギア比)
```

| 使い道 | 内容 |
|---|---|
| 実走 | そのまま挙動に出る。ドッカンターボは本当に扱いづらい |
| AI委託走行 | `t = t_ideal × (1 + k·(1 − driveability))` |
| 夜のバトル | 扱いにくい車は「タイヤの食わせ方」が難しく、ミス確率が上がる |
| プレイヤー技量 | `driverSkill` が上がると `k` が小さくなる。**プレイヤー自身の上達と、車の尖り方が噛み合う** |

`driverSkill` は走行距離・ベストラップ更新・バトル勝利で緩やかに上昇（上限あり）。
数値ではなく「ドライバー手帳」の記述（例：*低速ヘアピンの立ち上がりが安定してきた*）として提示する。

## 12. 信頼性・故障

```
stress_i = Σ (負荷/許容) の積算       // 回転数、筒内圧、温度、G、熱サイクル
hazard_i(t) = λ0_i × exp(β_i × stress_i) × (1 / q_grade) × wearFactor
P(故障) = 1 − exp(−∫ hazard_i dt)
```

| 部品 | 典型的な故障 | 予兆（プレイヤーに与えるヒント） |
|---|---|---|
| ピストン／リング | 溶損、抱き付き | ノック音、ブローバイ増、パワー感の低下 |
| コンロッド | 曲がり、破断 | 高回転での異音、油圧低下 |
| タービン | シャフト遊び、オイル漏れ | 白煙、ブースト立ち上がりの鈍化 |
| ミッション | ギア欠け、シンクロ摩耗 | シフトの渋り |
| クラッチ | 滑り | 回転だけ上がる |
| ブレーキ | フェード、ローター割れ | ペダルの奥、効きの低下 |
| ハブ／ベアリング | 異音、ガタ | 直進時の唸り |
| 電装／ECU | センサ異常、失火 | 間欠的な出力落ち |

**設計方針**
- 故障は**必ず予兆を出す**。無警告の全損は不快であり、学習にならない。
- 予兆の検出には**計測（データロガー、油温油圧計、ノックセンサ）** が必要 → 計器類も製造対象になる。
- 故障した部品は「故障解析」に回すと **D4 データが大量に得られる**。壊すことにも価値を与える。

## 13. 車両の走行シミュレーション（実走モード）

| 項目 | 仕様 |
|---|---|
| 物理ステップ | 固定 120 Hz（描画は可変、補間） |
| モデル | 4輪の簡易剛体＋荷重移動（ロール／ピッチは1次近似）。タイヤは §7 のMF |
| 自由度 | 平面3自由度（x, y, yaw）＋ピッチ／ロール角の擬似計算、サスストロークは1自由度/輪 |
| 荷重移動 | `ΔFz_long = m·a_x·h_cg / L`、`ΔFz_lat = m·a_y·h_cg / T`（スタビ剛性で前後配分） |
| 入力 | ステア（アナログ）、アクセル、ブレーキ、クラッチ、シフト（H/シーケンシャル）、サイド |
| 操作補助 | ABS／TCS／自動クラッチ／自動シフト／ライン表示／3秒巻き戻し（任意） |
| 疑似3D描画 | 物理は平面座標で解き、描画は区間投影（`07` §6.3） |

**手触りの方針**：フルシム（Assetto 相当）ではなく、**「挙動の理由がわかるアーケード」**。
スロットルオンでリアが出るのは LSD とタイヤ温度とトルク曲線の結果である、と説明できる範囲で簡略化する。
