# 04. 夜の首都高パート（オープンワールド・ドライビング）

> **夜は計測台である。** 走ることは娯楽であると同時に、工場の研究を止めないための必須作業である。

---

## 1. パートの目的と位置づけ

| 目的 | 得られるもの | 工場への接続 |
|---|---|---|
| **テレメトリ収集** | テレメトリ・パケット | 解析ラボ → **D5 データ**（研究の約25%がD5を要求） |
| 実地検証 | セットアップの妥当性、故障の予兆発見 | 設計の修正指針 |
| 資金 | バトルの賭け金、運び屋ミッション、ショップ受注 | 設備投資 |
| 評判（REP） | ライバル解禁、**コネクション市場の解放（30ごとに1枠・最大3枠）**、筑波の招待枠 | 進行解放 |
| 部品・情報 | 中古／希少パーツ、図面（研究のショートカット） | 工場レシピの解放 |

**1セッションの構造**：出庫 → 目標カード3枚（任意選択） → 帰庫。実時間 15–25 分。

## 3. 世界のシミュレーション

### 3.1 時刻・天候・路面

| 変数 | 範囲 | 影響 |
|---|---|---|
| 時刻 | 20:00–04:00 | 交通密度、警察密度、ライバル出現、照明 |
| 気温 | −2 〜 34 ℃ | 空気密度 → 出力、タイヤ温度の上がり方 |
| 路面温度 | 気温 −3 〜 +6 ℃ | タイヤμ |
| 天候 | 晴／曇／小雨／雨／豪雨／霧 | μ、視界、ハイドロプレーニング |
| 路面状態 | 乾／湿／濡れ／水膜 | μ 0.98 → 0.62。継ぎ目・白線・マンホールは局所的にさらに低い |
| 風 | 0–12 m/s | 橋梁区間での横風、湾岸の向かい風 |

雨の夜はネオンの反射が最も美しく、同時に最も危険——という**美しさと危険の一致**を設計の軸にする。

### 3.2 交通AI

| 種別 | 挙動 |
|---|---|
| 一般車 | 車線維持、50–80 km/h、合流時は譲る／譲らないが確率で決まる |
| トラック | 左車線、70 km/h、**視界を塞ぐ壁**として機能 |
| タクシー | 急な車線変更。最も危険な存在 |
| 流し（走り屋以外の速い車） | 90–120 km/h。バトルにはならないが読み合いになる |
| 工事規制 | 車線減少。ルート記憶が通用しなくなる動的要素（夜ごとに場所が変わる） |

- 交通密度は時刻で変動（22時：高 → 2時：低）。**密度が低い深夜ほどタイムは出るが、警察の注目も集まる**。
- 一般車との接触：車両ダメージ＋**通報（ヒート +12）**。死傷の描写は行わない（`09` §6）。

## 4. バトルシステム

### 4.1 ローリング（SPゲージ方式）

湾岸系／TXR系の「追走」を本作向けに再定義する。

```
初期SP: 両者 10,000
毎tick:
  gap = 先行車と後続車の距離 [m]
  if gap > 0:   後続のSP -= k_follow(gap) ;  先行のSP -= k_lead(gap)
  k_follow(gap) = base × (1 + gap/40)^1.5          // 離されるほど削れる
  k_lead(gap)   = base × 0.35 × (1 − min(gap,80)/80)  // 真後ろに付かれていると削れる
  追加減少: 一般車との接触 −400 / 壁接触 −900 / スピン −1,800
勝利条件: 相手のSPが0、または 400 m 以上引き離して10秒経過
```

| 要素 | 意図 |
|---|---|
| 先行も削れる | 逃げ切りだけでは勝てない。振り切る必要がある |
| 距離の非線形 | 僅差の攻防が長く続き、決定的瞬間がはっきりする |
| ミスの重さ | 1回のスピンで試合が決まる＝扱いやすい車の価値 |

### 4.2 バトル種別

| 種別 | ルール | 得られるもの |
|---|---|---|
| ローリング | 上記SP方式。C1／湾岸 | 賭け金、REP、D5（高品質） |
| ゼロヨン（0–400 m） | 停止から400 m。シグナルスタート | 駆動系・トラクションのデータ（D2） |
| ゼロヨン・ハイスピード（1 km） | 高速域の伸び | 空力データ（D3） |
| C1ラップ勝負 | C1一周のタイムで競う | 総合力の証明。REP大 |
| トップスピードラン（湾岸） | 設定区間の最高速 | 最高速記録、D3 |
| **タイムトライアル（計測走行）** | 対戦なし。区間タイムを縮める | **D5の最も安定した供給源** |

### 4.3 ライバル

| 階層 | 人数 | 内容 |
|---|---|---|
| 流し | 無制限 | ランダム生成。弱い。練習用 |
| ネームド | 24名 | 固有名・固有車・固有セリフ・固有セットアップ。図鑑に登録される |
| クルーリーダー | 6名 | 各クルーの頭。撃破でクルー全体が解禁／敵対 |
| **ゴースト** | 3名 | 噂だけの存在。特定条件（雨の3時台、C1を無停止で3周 等）で出現 |

ライバル車のスペックは**プレイヤーと同じ車両モデル**で生成する（チートなし）。
つまり「相手も部品を組んでいる」設定であり、撃破後に**相手のセットアップを閲覧できる**（学習材料になる）。

```ts
type Rival = {
  id: string; name: string; crew?: CrewId;
  carSpec: VehicleSpec;        // プレイヤーと同じ生成系
  driverSkill: number;         // 0..1
  aggression: number;          // ブロック頻度、リスクテイク
  preferredRoute: RouteId[];
  appearWindow: { from: Hour; to: Hour; weather?: Weather[] };
  wager: number;               // 賭け金
  dialog: DialogSet;           // 遭遇/勝利/敗北
};
```

### 4.4 遭遇フロー

```
並走 → ヘッドライトのパッシング（挑発）→ 相手が応じる／無視
  → 応じた場合：画面上部にバトルHUD（SPバー2本）が降りてくる
  → 決着 → 相手が減速して手を上げる（礼）→ 図鑑に記録 → 連絡先交換（次回PAで会話可能）
```

礼儀の演出を丁寧に作る。**本作の走り屋文化は暴力的ではなく、職人的である**というトーンを徹底する。

## 5. 取締りシステム（HEAT）

戦闘の代替となる「夜の圧力」。

### 5.1 ヒートの蓄積

```
heatRate = speedFactor + behaviorFactor + noiseFactor + areaFactor + reputationFactor
  speedFactor     : (v − 制限) が +40 km/h 超で急増（二次関数）
  behaviorFactor  : 車線変更の荒さ、追越、無灯火、接触、バトル中は×1.8
  noiseFactor     : 車両の排気音量 dB（静かな仕様は発見されにくい）
  areaFactor      : 区間ごとの警察密度（C1は高、湾岸東は低）
  reputationFactor: REPが高いほど注目される（有名税）
減衰: 法定速度で走る／PAで停車／帰庫 で毎分 −1.5
```

### 5.2 エンカウント

| ヒート | 事象 |
|---|---|
| 0–19 | 平穏 |
| 20–39 | 定置のオービス（固定位置、既知）。光ると罰金通知が後日届く |
| 40–59 | **覆面パトカー**が流れに紛れて出現。見分けは車種・アンテナ・ナンバー・挙動 |
| 60–79 | 覆面＋白バイ。追尾されると赤色灯 → **逃走フェーズ** |
| 80–94 | 出口・JCTに**検問**。ルート封鎖（マップに赤い線が引かれる） |
| 95–100 | 広域警戒。ヘリのサーチライト【P2】、帰庫路の封鎖 |

### 5.3 逃走フェーズ

- 「追尾中」ゲージが貯まると**停止命令**。従えば検挙（軽）／逃げれば重い結果。
- 逃走成功条件：視界から外れて 45 秒（トンネル、分岐、PA退避、下道へ降りる）。
- 逃走中は**テレメトリの品質が上がる**（本気の走行データ）。リスクとリターンの一致。
- **やらないこと**：パトカーへの体当たり、妨害、暴力的な排除。逃走は「交通の中に紛れる」手段に限定する。

### 5.4 ペナルティ

| 結果 | 内容 |
|---|---|
| 速度超過（軽） | 罰金 ¥25k–80k、ヒート +15 |
| 整備不良 | 罰金 ¥30k、**違反部品の使用禁止（車検対応まで）** |
| 著しい速度超過 | 罰金 ¥150k、免許点数、累積で**免停（3ゲーム日 走行不可）** |
| 共同危険行為（累積） | **車両押収（7ゲーム日）**。工場パートは継続可 |

**救済**：押収中も工場は動く。むしろ「走れない1週間」が工場に集中する時間を作る。
ペナルティが遊びを止めず、**別の遊びへ誘導する**設計にする。

### 5.5 ヒートと裏ルート

**ヒート70以上の週は、コネクション市場が完全に閉じる**（`10` §6）。
裏ルートの人間は、警察に見張られている走り屋と取引しない。
つまりヒートは「捕まるリスク」だけでなく、**調達経路の喪失**という経済的な罰も持つ。

### 5.6 走行中の入札

夜パート中、車内のスマホから深夜オークションに入札できる（`10` §10.2）。
締切の近い出品は HUD の端に小さく通知が出る。
**首都高を流しながら、信号待ちで ¥800,000 の上限を入れる**——
二大柱（昼の工場／夜の首都高）を、UI ひとつで繋ぐための仕掛けである。

## 6. テレメトリ → DATA の変換

### 6.1 収集

走行中、車両は常にログを取る（ロガー部品を装着している場合のみ記録精度が上がる）。

```ts
type TelemetryPacket = {
  routeId: RouteId;
  segments: SegmentLog[];      // 区間ごとの速度/G/舵角/スロットル/ブースト/温度
  quality: number;             // 0..1 : 走行の「濃さ」
  anomalies: Anomaly[];        // ノック検知、油温超過、失火、スリップ過大
  durationTicks: number;
};
```

```
quality = 0.25·攻めた割合(限界Gの80%以上で走った時間比)
        + 0.20·区間の多様性
        + 0.20·データロガーの等級
        + 0.20·バトル/逃走などの高負荷状況
        + 0.15·異常検出（壊れかけのデータは価値が高い）
```

### 6.2 変換

解析ラボで `TelemetryPacket` → `D5 データ ×N`。
`N = floor(基礎量 × quality × ラボ等級)`。**ただし同じ区間の繰り返しは逓減**（新しい区間・新しい条件を走る動機）。

### 6.3 区間アンロック型の研究

特定の研究は「特定区間の特定条件のデータ」を要求する。

| 研究例 | 要求 |
|---|---|
| 高速域空力の検証 | 湾岸線で 250 km/h 以上を 20 秒以上維持したログ |
| ブレーキ熱の実測 | C1谷町〜霞が関を連続3周、ブレーキ温度 400℃ 到達 |
| 雨天トラクション | 路面が濡れた状態で C1 一周を完走 |
| 低温始動と暖機 | 気温 5℃ 未満で出庫し、油温 80℃ まで到達 |
| 連続高負荷 | ブースト 1.8 bar 以上を 累計90秒 |

→ **「研究のために、こういう走り方をしに行く」**という夜の目的が常に生まれる。

## 9. 運転の手触り（Feel）

| 要素 | 仕様 |
|---|---|
| カメラ | 既定はボンネット後方の追従。車内視点／バンパー視点を選択可 |
| 速度感 | 画面端の流れ（街灯、継ぎ目、ガードレール）＋ FOV の動的変化（+6° @ 200km/h 以上） |
| 振動 | 路面の継ぎ目でコントローラ振動＋画面の微細な揺れ（強度調整可） |
| 音 | §`06` のエンジン音合成。トンネルで反響が切り替わる（リバーブ送り量の自動変化） |
| 視認性 | 雨の夜でも**進行方向が常に読める**ことを最優先。路面反射は美しさより可読性を優先して調整 |
| ミス回復 | スピン後の復帰を速く（巻き戻しなしでも 3–4 秒で再始動） |

### 9.1 「速い」と感じさせるための具体策

1. 100 km/h 以下では控えめ、180 km/h 以上で画面効果を一気に増やす（非線形の演出カーブ）。
2. 継ぎ目の音とフラッシュを**速度と同期**させ、リズムで速度を伝える。
3. 追い越す一般車との相対速度を誇張（視覚的にのみ 1.15 倍のパースを与える）。
4. 高速域でのわずかなステア不安定（空力と路面）。ただし破綻はさせない。

## 10. C1 一周タイムという第2の指標

筑波のラップと並ぶ、もう1つの公式記録。

| 項目 | 内容 |
|---|---|
| 計測 | C1外回り1周（14.6 km）。交通量・信号なし（高速道路のため）、ただし一般車あり |
| 基準 | 制限速度順守で 約17分30秒／Act0の車で 約14分／終盤の最適仕様で **9分台** |
| 変動要因 | 交通密度（時刻）、天候、ルート（内回り／外回り） |
| 記録条件 | 無接触・無検挙。接触した周回は参考記録扱い |
| 位置づけ | **筑波＝加速とコーナー、C1＝最高速と総合力**。2つの指標が異なる最適解を要求する |

この二重指標こそが「1台の至高のマシン」というテーマを成立させる。
筑波専用の空力仕様は C1 で遅く、C1 最高速仕様は筑波で遅い。
**両方で速い1台**を作ることが、本作の最終的な難題である（`05` §8 エンドゲーム）。
