## 2. マイルストーン（24ヶ月 + EA 12ヶ月）

| M | 名称 | 期間 | 完了条件（ゲート） |
|---|---|---|---|
| **M0** | 技術検証 | 0–3ヶ月 | ベルト10万アイテム@20Hzが8ms以内／疑似3Dで雨の夜が成立／決定論テストが通る |
| **M1** | **Vertical Slice** | 3–8ヶ月 | `01` §5 のオンボーディング60分が完走できる。工場Act0–1、筑波1コース、C1の1/3、品質・研究の最小形 |
| **M2** | 内部アルファ | 8–14ヶ月 | Act0–3 プレイ可能。流体・電力・空力・風洞。セーブ完全動作。20時間プレイで破綻しない |
| **M3** | クローズドベータ | 14–19ヶ月 | Act0–5。夜の全システム。バランス自動検証の整備。外部テスター50名 |
| **M4** | **Early Access 1.0** | 19–24ヶ月 | Act0–5 完成度8割、Act6 骨子。Steamページ、実績、ローカライズ（JA/EN） |
| **M5** | EA 更新 | 24–33ヶ月 | 四半期ごとの大型更新（Act6、MOD、ステアリング対応、追加コース） |
| **M6** | **1.0 リリース** | 36ヶ月 | 全Act、エンディング、週課ランキング、安定性、CERO/ESRB 申請完了 |

### 2.1 M1（Vertical Slice）の具体的な中身

これが**出資判断・採用判断・自分たちの継続判断**のすべての基準になる。

- 工場：48×48、ベルトT1/T2、マニピュレータ2種、加工機4種、計測ゲート、ダイナモ
- 品質：等級 C/B/A、工具摩耗、校正
- 車両：`tachibana_silka` 1台、部品12点、セットアップ8項目
- 走行：筑波 TC2000 フル、C1外回りの芝公園〜江戸橋（約4.6 km）
- 研究：12ノード
- 夜：テレメトリ収集＋ライバル1名＋覆面1種
- 所要プレイ時間：**90分**で「工場→部品→筑波→タイム更新」を2周できること

**Vertical Slice の合格判定**：外部プレイテスター10名のうち **7名以上が「続きをやりたい」と回答**。

## 3. スコープ管理（MoSCoW）

| 区分 | 項目 |
|---|---|
| **Must** | 工場自動化／品質・公差／研究（D1–D6）／車両モデル／筑波／C1／セーブ／決定論 |
| **Should** | 電力デマンド／流体／近隣圧／ヒート／ライバル／回路網／設計図／ゴースト |
| **Could** | 構内軌道／建設ドローン／MEZZANINE／自動セットアップ探索／ガレージ3D／MOD |
| **Won't（1.0では）** | リアルタイムマルチ／下道オープンワールド／VR／キャラ育成RPG要素／モバイル版 |

### 3.1 スコープ危険信号

次のいずれかが起きたら即座に縮小判断を行う。

- Vertical Slice が 9ヶ月を超える
- 1 tick の平均処理時間が M2 時点で 6 ms を超える
- ピクセルアセットの消化が計画比 70% を下回る
- 「工場と走行、どちらが主役か」の議論が2回以上蒸し返される（＝設計の破綻の兆候）

## 5. 法務・IP ガイドライン

### 5.1 自動車メーカー・車種 ― **実名ライセンス取得を前提とする**（判断ログ D-19）

本作は **実在車名を使用する**（`03` §2 の 8 台：AE86 / S15 / FD3S / CN9A / JZA80 / BNR32 / NA1 / S30）。
JDM カルチャーのディテールを売る作品で `4A-GE` を「K 系直 4」と書いた瞬間に、
本作が存在する理由が消えるためである。したがって**ライセンスは回避すべきコストではなく、必須の仕入れ**として扱う。

#### 5.1.1 取得計画

| 権利者 | 対象 | 着手 | 代替可能性 |
|---|---|---|---|
| トヨタ自動車 | AE86（スプリンタートレノ）、JZA80（スープラ） | **M6（垂直スライス前）** | 低（JZA80 は発注指定） |
| 日産自動車 | BNR32、S15、**S30（フェアレディZ 432）** | **M6** | **なし**（BNR32・S30 は発注指定） |
| マツダ | FD3S（RX-7） | M8 | 中（HERO CAR 既定だが S15 で代替可） |
| 三菱自動車 | CN9A（ランサーエボリューション IV） | M10 | 高 |
| ホンダ | NA1（NSX-R） | M10 | 高 |

- 日産・トヨタは **交渉決裂＝仕様変更**に直結するため、**プロトタイプ段階（M6）で先に当たる**。
- ゲーム内の描写方針を先に文書化して持ち込む：**改造は実在部品名を使わない／事故や破損の描写は車体の板金に留める／
  実在ドライバー・実在チームを登場させない／公道走行の違法性をUIで明示する**（§6）。

#### 5.1.2 不成立時のフォールバック（コード変更ゼロで切替）

```
車名表記は 3 層でデータ化する：
   displayName : "日産 スカイライン GT-R"     ← ライセンス取得時
   codeName    : "BNR32"                      ← 型式のみ（多くの場合、型式単体は商標性が低い）
   genericName : "直6ツインターボ AWD クーペ"  ← 完全フォールバック
```

- `content/locale/vehicles.json` に 3 層すべてを持ち、ビルドフラグ `VEHICLE_NAMING=licensed|code|generic` で切替。
- **内部 ID（`nissan_bnr32` 等）は変更しない**——セーブデータ互換を壊さないため。
- 3D モデル・ドット絵は**メーカー別にアセットを分離**し、不成立のマルクだけ差し替えられる構造にする。
- 外観の固有意匠（エンブレム、グリルの商標的要素）は**ライセンス取得後も個別許諾を確認**する。
- MOD での追加車種は**公式には関与しない**。ガイドラインで「第三者の権利を侵害しないこと」を明記。

### 5.2 地名・施設名

| 名称 | 方針 |
|---|---|
| 「首都高」「首都高速道路」 | 事業者の商標。**作品名・ストア表記には使わず**、作中では一般名詞的表現（`C1`、`都心環状`、`湾岸`）を主に用いる。必要に応じて使用許諾を打診 |
| 「C1」「湾岸線」 | 路線通称として使用。地図形状は再構成（実測再現をしない） |
| 「筑波サーキット」「TC2000」 | 施設名。**使用許諾の打診を推奨**。不可の場合は `TSUKUBA` を地名として扱い、コース名を `COURSE 2000` 相当の一般表記に差し替える（タイトルの `to TSUKUBA` は地名として維持） |
| PA名（辰巳・大黒・平和島） | 施設名。許諾が取れない場合は `T-PA` `D-PA` 等の通称表記に切替できるよう、**文言をデータ側に外出し**しておく |

> **設計上の保険**：すべての固有名詞は `content/locale/*.json` に外出しし、
> 差し替えがコード変更なしで可能な構造にする（`README` §2-3）。

### 5.3 音楽・フォント・素材

- 楽曲はすべてオリジナル（買い切り契約、クレジット明記）。既存曲・既存ジングルの使用禁止。
- エンジン音の収録素材は、**自社収録または商用利用可のライブラリ**のみ。車種名を素材名に残さない。
- フォントは商用利用可能なもの（Inter / IBM Plex / Noto / UD系）。ライセンス一覧を `ASSETS.md` に記録。

### 5.4 OSS ライセンス

- 依存ライブラリのライセンスを `tools/license-report.ts` で自動収集し、配布物に `THIRD_PARTY_NOTICES.txt` を同梱。
- GPL系の取り込みは行わない（MIT / Apache-2.0 / BSD のみ）。

## 6. 倫理・レーティング

### 6.1 表現方針

| 項目 | 方針 |
|---|---|
| 公道での速度超過 | **ゲーム内でも明確に違法**として扱う。制限速度を常時表示し、違反には必ず結果（罰金・押収）を与える |
| 人身事故 | **描写しない**。歩行者は登場させない。一般車との接触は物損と通報のみ |
| 警察 | 敵ではなく職務を遂行する大人として描く。暴力的な排除・妨害行為は実装しない |
| 暴走族的表現 | 集団による交通妨害・威嚇は扱わない。走り屋は「技術者と礼儀」の文脈で描く |
| 飲酒・薬物 | 扱わない |
| 起動時表示 | 「本作はフィクションです。現実の公道での速度超過および危険運転は法律で禁止されています」を初回起動時に表示（スキップ不可、2秒） |

### 6.2 レーティング想定

| 機関 | 想定 | 理由 |
|---|---|---|
| CERO | **B（12才以上対象）** | 犯罪行為（速度超過）の描写があるが、賛美せず結果を描く |
| ESRB | **T** | 同上 |
| PEGI | **12** | 同上 |

申請は M4（EA）前に実施。表現の変更が必要になった場合に備え、
「違反描写の強度」を**データで調整可能**にしておく（罰則の強さ、警告の頻度）。

## 7. 検証計画（プレイテスト）

### 7.1 テストの種類

| 種類 | 時期 | 人数 | 目的 |
|---|---|---|---|
| ハンズオン観察 | M1 | 10 | オンボーディング60分の詰まり所を特定 |
| 長時間テスト | M2 | 20 | 10時間プレイでの飽き・破綻・バランス |
| クローズドβ | M3 | 50–100 | Act0–5 の通し、バランス、バグ密度 |
| 専門家レビュー | M3 | 5 | 実際のチューナー／サーキット走行経験者に「嘘がないか」を見てもらう |
| アクセシビリティ監査 | M4 | 3 | 色覚・運動・認知の観点 |

### 7.2 計測する指標（合格基準）

| 指標 | 目標 |
|---|---|
| チュートリアル完走率 | ≥ 85% |
| 「最初の自動ライン」到達までの時間 | 中央値 ≤ 20 分 |
| Act1 到達率（2時間時点） | ≥ 70% |
| 「なぜタイムが縮んだか説明できる」回答率 | ≥ 80% |
| 夜パートを自発的に遊ぶ割合 | ≥ 75%（強制されたと感じる割合 ≤ 20%） |
| 10時間時点の継続意欲 | ≥ 70% |
| 重大バグ（進行不能・セーブ破損） | 0 |
| 平均 fps（推奨環境） | ≥ 60（1%low ≥ 45） |

### 7.3 観察のプロトコル

- 発話思考法（think-aloud）。**開発者は質問に答えない**（詰まりを観察するため）。
- 画面録画＋入力ログ＋`performance` ログを同時取得。
- 各セッション後に短いアンケート（5問、2分以内）。
