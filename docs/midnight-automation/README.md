## 2. 本書の前提と補完範囲

発注時点で提示されたのは **「1. プロジェクト基本概要」** と **「2. ゲームの二大柱とコア・ゲームプレイループ」の冒頭** までである。
それ以降（世界観設定の詳細、コアシステムの個別指定）は受領できていないため、本書では以下の方針で設計側が補完した。

1. 提示済みの要素（タイトル、ジャンル、視点／アートスタイル、コア・フィロソフィー、昼夜二分構造、
   「巨大シャッターを開けるとそのまま首都高の合流レーンへ出る」シームレス拠点）は **確定仕様として不可侵** に扱う。
2. 未受領の領域は、確定仕様から論理的に導かれる案を提示し、節見出しに `【補完】` を付す。
3. 差し替えが起きやすい箇所（固有名詞、年代、キャラクター、価格、プラットフォーム）は
   `08_data_schema_and_balance.md` の **データ定義側に外出し** し、文章を書き換えずに差し替えられる構造にした。

## 3. 設計判断ログ（Key Design Decisions）

後から「なぜこうなっているか」を失わないための記録。変更時はこの表に追記する。

| # | 判断 | 理由 | 却下した代替案 |
|---|---|---|---|
| D-01 | 工場の生産物は **車ではなく「実験データ（DATA）」と「1点物の部品」** | コア・フィロソフィーの直訳。量産販売を主目的にすると Factorio の劣化版になり、JDM文脈も死ぬ | 完成車を量産して販売する経営SLG（既存プロト `KOBO Motorworks` の方向） |
| D-02 | **公差（Tolerance）と歩留まり** を品質系の中心に据える | 「同じ部品でも精度が性能になる」というエンジニアリングの核。Factorioの「品質」とは異なり、**計測・補正・工具摩耗のフィードバックループ**という自動化パズルになる | 単純な星付きレア度 |
| D-03 | 敵・戦闘の代わりに **三種の圧力**（近隣圧／取締り圧／資金圧）を置く | 攻撃してくる敵がいないと拡張が無制限になり緊張が消える。日本の都市部工場＋走り屋という設定に最も自然な「反作用」 | 産業スパイ、暴力団、災害のみ |
| D-04 | 夜パートの主目的は **金ではなくテレメトリ（D5データ）** | 走ること自体が研究の必須入力になり、二大柱が一方通行でなく相互依存になる | 夜＝資金稼ぎ（工場が育つと夜に行く理由が消える） |
| D-05 | 進行ゲートは **筑波TC2000のラップタイム** | 「速さ」という一次元の明快な指標。あらゆるシステムの出力がここに合流する | 売上高、名声ポイント |
| D-06 | シミュレーションは **20Hz 固定ステップ・完全決定論** | リプレイ、ゴースト、ベンチマーク、セーブ互換、バグ再現のすべてがこれに依存する | 可変Δtの逐次更新 |
| D-07 | 工場は 2Dドット（クォータービュー）、走行は疑似3D。**3Dの統一は行わない** | 発注の確定仕様。加えて、2台の描画系を分ける方が少人数で到達可能な画質上限が高い | 全編3D |
| D-08 | ~~実在の自動車メーカー名・車種名は使わず **架空マルク** で統一~~ **【D-19 により撤回】** | ~~ライセンス交渉を前提にすると制作が止まる~~ | — |
| D-09 | 地名（首都高、C1、筑波）は **実在名を使いつつ、路線形状は再構成** | 固有名詞は作品の訴求の核。ただし測量再現はせず「記憶の中の形」に再構成し、権利・安全面の注意書きを添える（`09` §5） | 完全架空地名／完全実測再現 |
| D-10 | 放置進行（オフライン生産）は **資源のみ、研究は不可** | 工場を見に行く理由を残す。研究＝データ変換はプレイヤーの設計判断の結果であるべき | 完全放置可 |
| D-11 | ラップタイムは **走行シム本体ではなく準定常ソルバ** でも算出可能にする | セットアップ比較を「走らずに」評価できると、工場パートに設計の意味が生まれる（＝シミュレーション棟の価値） | 常に実走のみ |
| D-12 | Web技術（TS/WebGL2）で実装し、デスクトップ版は Tauri でラップ | 既存リポジトリ資産（Vite + React + TS + Cloudflare Pages/GH Pages）を継承でき、Web体験版という強力な集客導線が持てる | Unity / Godot / 独自C++ |
| D-13 | 章ゲートのタイムは **先に決めず、準定常ソルバの実行結果から決めた**（`shared/midnight/lap-solver.ts`） | 当初案（1:05 / 1:00 / 0:57 / 0:54 / 0:51）を実装して解いたところ**物理的に到達不能**と判明した。コース全長を公称 2,045 m に合わせ、走行ライン係数を実在の最速記録（非フォーミュラ 49秒445）に合わせて較正したうえで、各Actの想定スペックが**ゲートを 0.2〜0.8 秒だけ下回る**ように数値を置き直した。結果として最終到達点 Act6 は理論 **0:49.238**／推定 **0:49.582** となり、**実在の非フォーミュラ最速 49.445 秒は割らない**＝現実の最速クラスに並ぶところが天井になる（再較正の経緯は D-17） | 体感と雰囲気でタイムを置き、実装時に辻褄を合わせる（＝ゲートが到達不能／逆にヌルくなる事故が確定する） |
| D-14 | パーツとベース車の入手は **4つの市場**（カタログ／ヤード／オークション／コネクション）に分け、**乱数の軸を市場ごとに分離**する | ランダム性を1本の太いダイヤルにすると体験が「運の良い日／悪い日」に潰れる。4分割すれば「どの乱数を引き受けるか」がプレイヤーの戦略になる。さらに乱数は決定論シード＋床＋天井＋鑑定（＝情報を買うと分散が縮む）で囲い、**S/Legendary 等級は市場に流さない**ことで工場の存在意義を守る（`10` §8） | 単一の「ガチャ商店」／完全固定価格のショップ（どちらも選択が消える）／海外並行輸入を加えた5市場（薄まるため見送り） |
| D-15 | 4市場を **国内中古／輸入車／コンテナ／ローカル** へ再定義し、国内中古を **AA・ネトオク・解体ヤード・青カゴ**の4チャネルに分割する（正本は `spec/S3`） | 旧構成（カタログ／ヤード／オークション／コネクション）は乱数の軸では綺麗だったが、**日本の中古車文化の手触りが出なかった**。AA の出品票（評価点・修復歴R・検査員メモ）を読む行為そのものが「目利き」のゲームになり、コンテナのブラインド入札が純粋なガチャを引き受け、ローカルが金で買えない領域を担当する。乱数の軸の分離（D-14）は維持したまま、**題材の密度だけを上げた** | 旧4市場の維持（手触り不足）／市場を8つに増やす（薄まる）／AA を単なる価格表にする（目利きが消える） |
| D-16 | 最上位品質の呼称を **Legendary（伝説品質）** に統一し、要件を「公差 ±0.003 mm **かつ セット内重量差 0.001 g 以下**」とする | 旧称 `BP`（Blueprinting）は実機由来の正しい用語だが、**プレイヤーの語彙ではない**。「Legendary」は一目で最上位と分かり、0.001 g という現実離れした数値が逆にこの作品の狂気を象徴する。工程名としての「ブループリンティング（選別・摺り合わせ）」は残し、**工程名と等級名を分離**した | `BP` のまま（伝わらない）／`Mythic` 等の既存ゲーム用語（JDM の文脈から浮く） |
| D-17 | 走行ライン係数を **1.00 / 1.06（縁石区間）** に確定し、変速損失を**ノード境界で丸めず連続化**する | 1.03/1.10 では Act6 が 0:47.696 になり「49秒台の壁」という物語が消えた。0.97/1.02 では実効半径が幾何半径を下回り説明が苦しく、Act0〜5 が全滅した。**1.00/1.06＝イン・アウトを使い切れば縁石区間だけ 6% 大回りできる**が説明可能性と難易度の両立点。さらに変速損失をノード境界で丸めていた実装では **+10 PS で 0.009 秒遅くなる**量子化ノイズが出ていたため、覆われた割合だけ駆動力を減らす連続化に変更し、符号反転を解消した（+10 PS → −0.040 秒） | 1.08/1.22・1.05/1.15・1.03/1.10・0.97/1.02（いずれも却下）／変速時間を単純加算（物理的に過大） |
| D-18 | 車体剛性 → グリップの変換を **μ_eff = μ0 × clamp(0.88 + 0.12 × 剛性係数, 0.60, 1.05)** に改め、**レストア完遂車が新車を超える**（剛性 1.37〜1.44）ことを数式で保証する | 旧式 `0.90 + 0.10 × 剛性` は剛性 1.0 で頭打ちになり、「サビだらけの不動車を完全復活させると新車を凌駕する」というユーザー要件を表現できなかった。上限 1.05 を置くのは、剛性がある点から先はタイヤの仕事を邪魔しなくなるだけで、青天井にすると「剛性だけ上げれば勝てる」になるため | 上限なし（剛性一本足になる）／旧式のまま（レストアの報酬が出ない） |
| **D-19** | **D-08 を撤回し、実在車名を使用する**。市場プール8台はすべて実在名＋型式＋実在エンジン型式で定義（`03` §2）。発注で名指しされた **BNR32 / JZA80 / S30Z** を必ず含める | 発注仕様の明示的指示。本作は「JDM マニアが唸るディテール」が目的であり、`4A-GE` を `K-系直4` と書いた瞬間にその目的が死ぬ。ライセンスは**実装前に取得する前提**とし、未取得時のフォールバックとして型式コード（`BNR32` 等の記号）のみを残せる構造にしておく（`09` §5.1.2） | 架空マルク（D-08・却下）／型式コードのみ（記号として弱い） |
| **D-20** | **S30Z を `wreckOnly: true` とし、AA・奇跡枠には一切出さない**。解体ヤード・コンテナ・海外納屋からのみ、サビ 80〜95% の不動車として出現させる | 発注仕様が「サビ進行度80%以上の不動車としてレストア対象」と役割まで指定している。健全な個体が普通に買えてしまうと、レストアライン（`spec/S4` 全13工程）とレストアの報酬（剛性 1.37〜1.44）が存在意義を失う。実装は `availableChassis()`／`wreckChassis()` の 2 関数で分離 | 全市場に出す（レストアが無意味になる）／固定イベント配布（ランダム性の要件に反する） |
| **D-21** | **『PROJECT 49』の解禁を「6 派閥すべての制覇」とし、筑波のタイムだけでは開かない**。派閥は路線＝縄張りで分割（C1内回り／C1外回り／湾岸／横羽／大黒／全線） | 発注仕様「各派閥を完全制覇後に解禁」。設計上の意味は**二大柱のどちらか片方だけでのクリアを塞ぐ**こと。工場だけ育てた者は夜で止まり、走り込んだだけの者は 49 秒台に届かない。制覇は「その縄張りの走行ログ価値 +15%」として自動化側にも還元する | タイムのみ解禁（夜パートが消化試合になる）／総撃破数で解禁（場所の記憶が育たない） |

## 4. 用語集（Glossary）

| 用語 | 定義 |
|---|---|
| **TICK** | シミュレーションの最小時間単位。1 tick = 50 ms（20 tick/s）。工場・経済・時間経過はすべて tick で駆動する |
| **ゲーム日（GD）** | ゲーム内の1日。`昼フェーズ`＋`夜フェーズ`で構成。既定で実時間 約14分（`01` §6） |
| **HERO CAR** | プレイヤーが最終的に1台だけ仕上げる主役車両。全システムの出力が集約される |
| **DATA（D1〜D6）** | 研究の投入資源。Factorio のサイエンスパック相当だが、**物理的な試験の副産物**として生成される（`05` §3） |
| **公差 / Tolerance** | 部品の設計寸法からの許容誤差。`±0.100 mm` 〜 `±0.003 mm` の7段階 |
| **等級 / Grade** | 公差判定の結果（`C` / `B` / `A` / `S` / `LEGENDARY`）。`LEGENDARY` は選別・摺り合わせ済みのブループリント品 |
| **歩留まり / Yield** | 投入数に対する目標等級到達数の比率 |
| **工程能力 Cpk** | 工程の安定度指標。機械の等級分布を決める内部値（`02` §9） |
| **近隣圧 / NUISANCE** | 騒音・排気・排水・振動により蓄積する行政＆近隣からの圧力（0–100） |
| **取締り圧 / HEAT** | 夜間走行で蓄積する警察側の警戒度（0–100）。覆面・検問・オービスの出現率を支配する |
| **SPゲージ** | 夜のローリングバトルにおける気力／集中の残量。相手との距離差で減少する |
| **テレメトリ・パケット** | 夜間走行で取得する生ログ。解析ラボで D5 に変換される |

## 8. 変更管理

- 本バンドルの数値（バランス値）は `08_data_schema_and_balance.md` の表を **単一の正** とする。他ドキュメントの数値は引用。
