## 1. 方式：準定常（Quasi-Steady-State）ラップソルバ

過渡（ヨー慣性・タイヤの緩和長・サスの動き）を解かず、**各点で車が限界にいる**と仮定する。
レーシングカー設計の現場で使われる古典的な手法であり、
**部品の数値変更がラップタイムに何秒効くか**を安定して返す——本作に必要なのは正にそれである。

```
① コースを 2 m 刻みのノードへ離散化（TC2000 = 1,023 ノード）
② 各ノードの旋回限界速度を計算（ダウンフォースが v に依存するので不動点反復 8 回）
③ 前進パス：駆動力・トラクション・空気抵抗・勾配・変速損失で加速を積分
④ 後退パス：制動限界で減速を積分
⑤ ②③④ の min を速度プロファイルとし、3 周分反復して収束させる（周回の繋ぎ）
⑥ dt = 2·Δs/(v_i + v_j) を全ノードで積算 → 理論ラップ
⑦ ドライバビリティ補正 → 推定ラップ
```

計算コスト：**1 ラップ約 0.8 ms**（M1 Mac, Node 22）。1,000 本のセットアップ探索が 1 秒で回る。

## 4. 支配方程式

### 4.1 実効旋回半径（走行ライン）

```
R_eff = R_geom × LINE_RADIUS_GAIN           （通常区間）
R_eff = R_geom × LINE_RADIUS_GAIN_KERB      （kerbUsable 区間）

LINE_RADIUS_GAIN      = 1.00   ← 確定（判断ログ D-17）
LINE_RADIUS_GAIN_KERB = 1.06
```

**較正の経緯**：1.03/1.10 では Act6 が 0:47.696 になり、「49 秒台」の達成感が消えた。
0.97/1.02 では実効半径が幾何半径を下回り、物理的な説明が苦しい上に Act0〜5 が全滅した。
**1.00/1.06**＝「イン・アウトを使い切れば縁石区間は 6% だけ大回りできる」が、
説明可能性と難易度の両立点である。不足分は Act 別のスペック側で吸収した。

### 4.2 グリップ（荷重感度つき）

```
F_z     = m·g + ½·ρ·(C_Lf + C_Lr)·A·v²
μ(v)    = μ₀ · (F_z / F_z0)^(−k_load) · μ_surface · k_cond · (1 − 0.35·wear^1.8)
F_grip  = μ(v) · F_z

  k_load = 0.16（荷重感度。荷重が倍になるとμが約 10.5% 落ちる）
```

**荷重感度があるから、ダウンフォースは「増やすほど効率が落ちる」**。
これが無いと「翼を無限に大きくする」が最適解になってしまう。

### 4.3 駆動力と変速損失

```
gear       = レブリミットを超えない最も低いギア（v に対して単調 → ハンチングしない）
             ダウンシフトは rpm < rpmLimit × 0.94 のヒステリシスつき
ratio      = gearRatios[gear] × finalDrive
rpm        = v / (2πr) × 60 × ratio
F_drive    = T(rpm) × ratio × η / r
m_eff      = m + 4·I_wheel/r² + I_engine·ratio²/r²     （回転慣性の等価質量化）
```

**変速損失の扱い（判断ログ D-17）**：`shiftTimeS` を単純加算する方式は過大だった。
採用したのは「**駆動力ゼロで惰行する距離**」として消化する方式である。

```
アップシフト時： shiftRemainingM += v · shiftTimeS
各ノードで    ： coastM        = min(Δs, shiftRemainingM)
                driveDutyRatio = 1 − coastM / Δs
                F_drive_eff    = driveDutyRatio × min(F_drive, F_traction)
```

> さらに **ノード境界で丸めない**ことが決定的だった。丸めていた頃は、
> Act4 で +10 PS すると **0.009 秒遅くなる**という量子化ノイズが出ていた。
> ノードを部分的に覆う連続化で符号反転が消え、+10 PS → **−0.040 秒**と正常化した。

### 4.4 トラクション限界（荷重移動と摩擦円）

```
ellipse     = √(1 − min(1, F_lat/F_grip)²)                … 横Gを使っている分、縦に使えない
driveShare  = AWD: 1.0
              FR/MR: clamp(1 − wdF + a_x·h_cg/WB, 0.15, 0.95)
              FF   : clamp(    wdF − a_x·h_cg/WB, 0.15, 0.95)
F_traction  = F_grip × driveShare × ellipse                （a_x を 2 回反復して自己無撞着に）
```

### 4.5 走行抵抗

```
F_drag = ½·ρ·C_d·A·v²
F_roll = 0.013 · m · g
F_grade= m · g · sin(θ)
a      = (F_drive_eff − F_drag − F_roll − F_grade) / m_eff
```

### 4.6 制動

```
F_brake = min( F_grip × ellipse , brake.maxTorqueNm / r )
decel   = (F_brake + F_drag + F_roll − F_grade) / m
```

**`maxTorqueNm / r` の項が効く**＝ブレーキが弱いとタイヤを使い切れない。
Act6 の 13,000 N·m は「タイヤ限界で止まれる」最小値として決めてある。

### 4.7 旋回限界（不動点反復）

```
v ← v + 0.7 · ( √( (F_grip(v) + m·g·sin(bank)) · R_eff / m ) − v )   × 8 回
```

ダウンフォースが v に依存するため、陽には解けない。8 回で 0.01 km/h 未満に収束する。

## 5. 時間積分とラップの確定

```
dt_i   = 2·Δs / (v_i + v_{i+1})
T_ideal = Σ dt_i
T_est   = T_ideal × (1 + 0.035 × (1 − driveability))
```

**理論ラップと推定ラップを分けている**理由：
「数字の上では 49.2 秒の車」が「乗ると 49.6 秒しか出ない」状況を作るため。
`driveability` を上げる（＝ 乗りやすくする）こともまた 0.4 秒の開発項目になる。

## 6. 車体剛性 → グリップ（S4 との接続）

```
μ_eff = μ₀ × clamp( 0.88 + 0.12 × stiffnessFactor , 0.60 , 1.05 )
```

| 車体 | stiffnessFactor | μ 倍率 | 筑波への影響（Act6） |
|---|---|---|---|
| 歪んだ事故車（bend 4mm・rust 0.6） | 0.59 | ×0.951 | **+1.0 秒** |
| 中古の良個体 | 0.92 | ×0.990 | +0.2 秒 |
| 新車 | 1.00 | ×1.000 | 基準 |
| **完全レストア**（S4 §5） | **1.37** | **×1.044** | **−0.9 秒** |
| ドライカーボンモノコック | 1.52 | ×1.050（上限） | −1.0 秒 |

> **上限 1.05 を置いた理由**：剛性はある点から先、タイヤの仕事を邪魔しなくなるだけで、
> それ以上は速くならない。青天井にすると「剛性だけ上げれば勝てる」になってしまう。

## 8. なぜ 1,020 PS が要るのか（本作の核心）

感度表を見てほしい。**Act6 では +100 PS がわずか −0.072 秒しか効かない。**
16 区間のうちパワーが支配的なのは**バックストレートただ 1 区間**で、残りはすべて
トラクション／ブレーキ／横G で頭打ちになっている。

> つまり **1,000 PS は「速さを買う」ために要るのではない。**
> **602 kgf のダウンフォースと Cd 0.50 の抗力を背負ったまま、437 m のバックストレートを
> 走り切るために要る。** エアロを削れば抗力は減るが、13 コーナーすべてが遅くなる。
> だから翼は外せない。だから 1,000 PS が要る。

これが「1,000 PS 超の内製エンジン ＋ 巨大エアロ」という目標設定の**物理的な正当化**である。
そして μ₀ +0.05 が −0.986 秒と最も効くことが、「全パーツ Legendary 品質」
（＝ 車体剛性 1.37 → μ +4.4%）の価値を支えている。

## 10. API

```ts
import { solveLap, formatLapTime, STANDARD_CONDITIONS } from "@/shared/midnight/lap-solver";
import { TSUKUBA_TC2000 } from "@/shared/midnight/tsukuba";

const r = solveLap(TSUKUBA_TC2000, spec, STANDARD_CONDITIONS);

r.idealLapTimeS      // 49.238
r.estimatedLapTimeS  // 49.582
formatLapTime(r.estimatedLapTimeS)  // "0:49.582"

r.vMaxKph            // 257

```

`segmentLimits` は UI の「次に何を直すべきか」の提示にそのまま使う（S6 §5）。
